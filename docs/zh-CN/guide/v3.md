# 从 v3 迁移

ZCF v5 是一次重写（没有 v4）。它不读取 v3 的设置，也不接受 v3 的命令。v3 仍保留在 npm 上，你可以继续使用：

```bash
npx zcf@3
```

它的源码位于 [`zcf@3.7.3`](https://github.com/UfoMiao/zcf/tree/zcf@3.7.3) 标签。

## 有哪些变化

| v3 | v5 |
|----|----|
| 配置 Claude Code 和 Codex，各自回答一套问题 | 一份配置应用到 Claude Code、Codex、Gemini CLI、OpenCode、Cursor CLI、Pi 和 DeepSeek Harness |
| 一连串提问菜单 | 终端（`zcf`）和浏览器（`zcf ui`）中的表单编辑器，或一个普通 JSON 文件 |
| 边回答边修改 | `zcf plan` 先以 diff 显示所有修改；`zcf apply --yes` 才真正执行 |
| 设置复制自 ZCF 自己的模板 | 按键修改每个工具的原生设置 |
| 供应商预设内置在每个版本中 | [预设](./providers)从仓库下载，无需发布新版本即可更新 |

## 命令

| v3 | v5 |
|----|----|
| `zcf`（菜单） | `zcf`（终端编辑器），或 `zcf ui` |
| `zcf init` / `zcf i` | `zcf init`，一条命令带选项完成：`zcf init --preset 302ai --api-key sk-... --tools claude-code --yes` |
| `zcf i -s -p 302ai -k "sk-..."` | 同上例；见[命令](./commands) |
| `zcf update` / `zcf u`（工作流） | 技能，通过配置中的 `skills`；工作流捆绑包见 `workflows` |
| `zcf check-updates` | `zcf update`（各工具自带的更新命令） |
| `zcf config-switch` | 配置中的供应商档案，用 `zcf switch <id|名称>` 切换 |
| `zcf ccr` | v5 不再包含。ZCF 不是网关；请把工具直接指向你的路由。 |
| `zcf ccu` | `zcf ccu`，直接透传给 [ccusage](https://ccusage.com) 本体 |
| CCometixLine | [extras](./config#extras) 中的 `ccline` |
| `zcf uninstall` | `zcf uninstall`，同时移除 ZCF 为工具写入的设置。 |

## 工作流与输出风格

v3 会把自己的工作流、agent 和输出风格复制到 Claude Code。v5 把这些工作流作为内置技能提供：在“技能”页或配置的 `skills` 中勾选；同样的 agent 和输出风格作为内置模板提供，见 `agents` 和 `styles`。ZCF 会用 `npx skills add` 和自己的文件写入，为每个已选工具安装它们。

## 迁移你的设置

v5 不导入 v3 的设置，也不会改动 v3 写入的内容。迁移步骤：

1. 运行 `npx zcf` 并填写供应商。选择一个[预设](./providers)最快。
2. 在“MCP 服务”页添加你的 MCP 服务。
3. 运行 `zcf plan` 检查 diff。ZCF 管理的键会被替换，文件中的其他内容保持不变。
4. 在编辑器中应用，或运行 `zcf apply --yes`。
