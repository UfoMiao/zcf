# v3 からの移行

ZCF v5 は書き直された新しいバージョンです（v4 はありません）。v3 の設定は読み込まず、v3 のコマンドも受け付けません。v3 は npm に残っており、引き続き使えます。

```bash
npx zcf@3
```

ソースは [`zcf@3.7.3`](https://github.com/UfoMiao/zcf/tree/zcf@3.7.3) タグにあります。

## 変わったこと

| v3 | v5 |
|----|----|
| Claude Code と Codex を、それぞれ別の質問で設定する | 1 つの設定を Claude Code、Codex、Gemini CLI、OpenCode、Cursor CLI、Pi、DeepSeek Harness に適用する |
| 質問形式のメニュー | ターミナル（`zcf`）とブラウザー（`zcf ui`）のフォームエディター、またはプレーンな JSON ファイル |
| 回答するたびに変更される | `zcf plan` がまずすべての変更を diff で表示し、`zcf apply --yes` で変更する |
| ZCF 独自のテンプレートに設定をコピーする | 各ツールのネイティブ設定をキー単位で編集する |
| プロバイダープリセットが各リリースに組み込まれている | [プリセット](./providers) はリポジトリからダウンロードされ、リリースなしで更新される |

## コマンド

| v3 | v5 |
|----|----|
| `zcf`（メニュー） | `zcf`（ターミナルエディター）、または `zcf ui` |
| `zcf init` / `zcf i` | `zcf init`。オプションだけで 1 回で完了します: `zcf init --preset 302ai --api-key sk-... --tools claude-code --yes` |
| `zcf i -s -p 302ai -k "sk-..."` | 上の例と同じです。[コマンド](./commands) を参照してください |
| `zcf update` / `zcf u`（ワークフロー） | 設定の `skills` によるスキル。ワークフローのバンドルは `workflows` にあります |
| `zcf check-updates` | `zcf update`（各ツール自身のアップデーター） |
| `zcf config-switch` | 設定のプロバイダープロファイル。`zcf switch <id|名前>` で切り替えます |
| `zcf ccr` | v5 には含まれません。ZCF はゲートウェイではありません。ツールを直接ルーターに向けてください。 |
| `zcf ccu` | `zcf ccu`。[ccusage](https://ccusage.com) 本体への透過です |
| CCometixLine | [extras](./config#extras) の `ccline` |
| `zcf uninstall` | `zcf uninstall`。ZCF が書き込んだ設定も一緒に削除します。 |

## ワークフローと出力スタイル

v3 は独自のワークフロー、エージェント、出力スタイルを Claude Code にコピーしていました。v5 は同じワークフローを内蔵スキルとして提供します。Skills ページまたは設定の `skills` で選べます。同じエージェントと出力スタイルも内蔵テンプレートとして提供され、`agents` と `styles` にあります。ZCF が `npx skills add` と独自のファイル書き込みで、選択した各ツールにインストールします。

## 設定の移行

v5 は v3 の設定を取り込まず、v3 が書き込んだ内容もそのまま残します。移行するには:

1. `npx zcf` を実行してプロバイダーを入力します。[プリセット](./providers) を選ぶのが最も早い方法です。
2. **MCP servers** ページで MCP サーバーを追加します。
3. `zcf plan` を実行して diff を確認します。ZCF が管理するキーは置き換えられ、ファイル内のそれ以外の内容は残ります。
4. エディターから適用するか、`zcf apply --yes` を実行します。

v3 の日本語ドキュメントは [`zcf@3.7.3`](https://github.com/UfoMiao/zcf/tree/zcf@3.7.3/docs/ja-JP) タグに残っています。
