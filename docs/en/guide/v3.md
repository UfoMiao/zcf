# Coming from v3

ZCF v5 is a rewrite (there was no v4). It does not read v3's settings or accept v3's commands. v3 stays on npm, and you can keep using it:

```bash
npx zcf@3
```

Its source is at the [`zcf@3.7.3`](https://github.com/UfoMiao/zcf/tree/zcf@3.7.3) tag.

## What changed

| v3 | v5 |
|----|----|
| Configures Claude Code and Codex, each with its own questions | One config applied to Claude Code, Codex, Gemini CLI, OpenCode, Cursor CLI, Pi and DeepSeek Harness |
| A menu of prompts | A form editor in the terminal (`zcf`) and in the browser (`zcf ui`), or a plain JSON file |
| Changes are made as you answer | `zcf plan` shows every change as a diff first; `zcf apply --yes` makes them |
| Settings copied into ZCF's own templates | Each tool's native settings, edited key by key |
| Provider presets built into each release | [Presets](./providers) downloaded from the repository, so they update without a release |

## Commands

| v3 | v5 |
|----|----|
| `zcf` (menu) | `zcf` (terminal editor), or `zcf ui` |
| `zcf init` / `zcf i` | `zcf init`, one run from flags: `zcf init --preset 302ai --api-key sk-... --tools claude-code --yes` |
| `zcf i -s -p 302ai -k "sk-..."` | The same, as the example above; see [Commands](./commands) |
| `zcf update` / `zcf u` (workflows) | Skills, through `skills` in the config; workflow bundles under `workflows` |
| `zcf check-updates` | `zcf update` (each tool's own updater) |
| `zcf config-switch` | Provider profiles in the config, switched with `zcf switch <id|name>` |
| `zcf ccr` | Not part of v5. ZCF is not a gateway; point the tools at your router directly. |
| `zcf ccu` | `zcf ccu`, passed through to [ccusage](https://ccusage.com) itself |
| CCometixLine | `ccline` under [extras](./config#extras) |
| `zcf uninstall` | `zcf uninstall`, which also takes the settings ZCF wrote for a tool out. |

## Workflows and output styles

v3 copied its own workflows, agents and output styles into Claude Code. v5 ships the same workflows as built-in skills — pick them on the Skills page or under `skills` in the config — and the same agents and output styles as built-in templates, under `agents` and `styles`. ZCF installs them with `npx skills add` and its own file writes for each selected tool.

## Moving your settings over

v5 does not import v3's settings, and it leaves what v3 wrote in place. To move over:

1. Run `npx zcf` and fill in your provider. Picking a [preset](./providers) is the quickest way.
2. Add your MCP servers on the MCP page.
3. Run `zcf plan` and check the diff. Keys ZCF manages are replaced; everything else in your files stays.
4. Apply from the editor, or run `zcf apply --yes`.
